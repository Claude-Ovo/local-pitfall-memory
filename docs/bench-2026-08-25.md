# Attribution engine benchmark

`Qwen3-4B-int4-ov` @ OpenVINO CPU (desktop, no GPU/NPU). Corpus: 26 error blocks = **6 mined from real Sensei sessions** (`tests/build_corpus.py`, redacted at extraction) **+ 20 curated** canonical node/python/git/docker/powershell errors (`tests/corpus/curated_errors.jsonl`).

## Reading the numbers

- **JSON validity 100 %** (26/26 parsed on the first try, `/no_think` honoured) — the property the attribution path actually depends on.
- **Latency**: p50 10.5 s, p95 14.7 s, first call 16.1 s, server cold start 9.4 s (includes the embedder). Confirms the design rule: the model must stay **off** the lookup path; it only runs once per new pit at `propose`.
- **Peak RSS 4.9 GB** for the resident server (4B INT4 + bge) → `info.json.mem_need_gb = 6.0` is the right budget.
- **error_class agreement 53.8 %** is a *string-overlap* metric between the deterministic regex class and the model's label, and it undersells the model. Reading the 12 "disagreements": 5 are cases where the regex found **no** class at all (git/docker/node "Cannot find module" have no `XxxError` token — det = `-`) and the model supplied a sensible one; the other 7 are the model choosing a **more specific semantic label** (`PortConflict` for EADDRINUSE, `CUDAOutOfMemory` for RuntimeError, `DependencyConflict` for npm ERESOLVE, `NetworkError` for FetchError). Zero cases of a *wrong* class. Root-cause guesses: 25/26 correct on manual read, 1 empty (UnicodeDecodeError).
- Decision: **4B stays.** An 8B control run would roughly double latency on CPU for no visible gain on this task.

## Provenance (added 2026-08-26, codex #3 P1)

- Hardware: Intel Xeon E5-2673 v3 @ 2.40 GHz (12C/24T, AVX2, no GPU/NPU used), 64 GB RAM, Windows 10 Pro 19045, power plan Balanced.
- Software: Python 3.13 venv, openvino-genai 2026.3.0.0 / openvino 2026.3.0 (requirements.txt pins), model `OpenVINO/Qwen3-4B-int4-ov` + `OpenVINO/bge-base-en-v1.5-int8-ov`.
- Command: `python tests/bench_model.py` at repo HEAD `e96fe6b` (the commit that added this file); corpus `tests/corpus/real_errors.jsonl` (6) + `tests/corpus/curated_errors.jsonl` (20).
- Runs: a single pass (n = 26, one call per block, warm server after the first call). Variance across repeated passes was not measured; treat latency as indicative, not a distribution.
- Manual scoring: one reviewer (the author) read each `root_cause_guess` against the known cause of the corpus block; "correct" = names the actual cause or an equivalent fix direction, "empty" = model returned an empty string. The per-row table below is the full record.
- The "8B would roughly double latency" line is an expectation from parameter count, not a measured control run.
